# Godot Base Bench — integration checkpoint

Checkpoint date: 2026-07-26

## Decision being tested

The native Godot prototype reproduced the desired module rotation and node
snapping more naturally than the current Three.js editor. This checkpoint tests
whether that interaction can live inside Orbital Ventures without prematurely
replacing the existing web stack.

The result is a technically successful hybrid prototype, not yet a production
decision. Godot is lazy-loaded behind a **Godot test** toggle in the Base Bench;
turning the toggle off immediately restores the Three.js view.

## Repository layout

- `godot-base-bench-src/` — authoritative, editable Godot 4.7 project.
- `godot-base-bench/` — generated Web export loaded by the iframe.
- `src/render.js` — Base Bench toggle, bridge, state mapping, lifecycle, and
  Three.js fallback.
- `src/shell.html` — iframe and integration-status presentation.
- `tests/test-assembly3d.js` — renderer-neutral integration contract checks.
- `build/game.js`, `index.html`, and `orbital-ventures.html` — generated by
  `node build.js`.

Do not hand-edit `godot-base-bench/` or the three normal web build artifacts.
Change `godot-base-bench-src/` or `src/`, then regenerate.

## Integration architecture

```text
Orbital Ventures state
        |
        | postMessage: load
        v
Godot Web iframe
        |
        | postMessage: layout_changed
        v
state.assemblyLayouts

Godot disabled -> existing Three.js Base Bench resumes
```

Messages cross the iframe boundary as JSON strings and carry a fixed `source`
field so unrelated `message` events are ignored. The parent also verifies that
the message originated from the current Godot iframe.

Parent-to-Godot `load` payload:

- `body`
- `facility_id`
- ordered module ID inventory
- position, yaw, hidden state, parent module ID, and docking-port names

Godot-to-parent `layout_changed` payload:

- position and yaw
- hidden/tray state
- parent module ID
- target and own docking-port names

The returned layout is translated into the existing `state.assemblyLayouts`
shape through `assembly3dWriteLayout()`. Simulation-owned module order is never
mutated.

## What works now

- Left-drag positioning with rigid connection-node snapping.
- Module rotation in 90-degree steps.
- Free orbit camera and zoom.
- Delete-to-tray, restore-from-tray, clear canvas, and reset layout.
- Lazy iframe startup only after the user chooses **Godot test**.
- Orbital Ventures module inventory and saved layout load into Godot.
- Godot layout changes return through the existing presentation-layout model.
- Godot can be disabled and re-enabled without reloading its runtime.
- The hidden Three.js renderer is paused while Godot owns the Base view.

## Important limitations

### Duplicate module types

The prototype currently keys modules by their catalog ID. It can represent one
`can_std`, one `lab_mod`, and so on, but cannot independently represent two
instances of the same type. Real facilities can contain duplicates, so this is
the first correctness blocker for production use.

The bridge advertises this honestly:

- `unique_module_types: true`
- `duplicate_module_types: false`
- `layout_round_trip: true`

### Distribution size

The generated Godot directory is about 39.9 MB, almost all of it the engine
WASM. Combined with the current 18.6 MB single-file release, the checkout ships
about 58.5 MB / 55.8 MiB of browser payload before server compression.

Lazy loading prevents this cost for players who never enable Godot, but a
production Godot view would materially change the game's download and caching
strategy.

### HTTP hosting

The normal Orbital Ventures build can be opened directly from `file://`.
Godot's WASM/PCK assets must be served over HTTP, so the hybrid build is no
longer a truly self-contained HTML file.

### Scope

- Only the Base Bench is connected.
- Station's vertical and linear docking work remains in Three.js.
- The bridge persists presentation layout, not new simulation mechanics.
- There is no schema migration/version negotiation beyond bridge version `1`.
- Deployment headers, cache policy, compression, and offline behavior have not
  been production-tested.

## Recommended restart task

Start with stable per-instance module identity:

1. Give every facility module instance a persistent instance ID independent of
   its catalog/type ID.
2. Change the bridge layout from a dictionary keyed by type to an ordered array
   keyed by instance ID.
3. Allow Godot to spawn any number of instances from a shared module
   specification.
4. Verify duplicate placement, rotation, deletion, snapping, save/reload, and
   Godot/Three.js toggling.
5. Re-measure the exported payload and startup time before expanding the test
   to Station.

Do not integrate Station or replace the Three.js default until duplicate
instances and real save/reload behavior pass. Those are the go/no-go gates; UI
polish is secondary.
